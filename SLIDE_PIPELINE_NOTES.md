# Slide pipeline — issues to iron out / ways to work better

Working notes from the 2026-05-22 cleanup. Source of truth = `methodology/`; `core_content/` is generated by `tools/00_extract_slides.py` (which calls `migrate_to_meta.build_meta_yaml`).

## Confirmed bugs

1. **`extract_order` produces duplicate `order` values** (`tools/migrate_to_meta.py:215`). Order is parsed from the filename's `mX_N[letter]` prefix, so:
   - **Prefix collisions:** two real slides sharing a prefix get the *same* order — e.g. `m4_1b_approach_to_dqa.md` and `m4_1b_fastr_vs_dhis2_dqa.md` both → `1.02`; `m4_1c_*` ×2 → `1.03`.
   - **Parse failures fall through to `0`:** multi-letter suffixes don't match the regex — `m4_3ab_*`, `m4_s3bb_*`, `m4_s0_*` → default `0`, colliding with `m4_0_*`.
   - **Fix idea:** after sorting in `build_meta_yaml`, break ties deterministically (nudge equal `(variant, order)` by sorted position); broaden the suffix regex to handle `3ab`, `s3bb`, etc.

2. **Extractor never deletes stale files.** When a slide is renamed/restructured in methodology, the old `core_content` file lingers next to the new one — e.g. FR `mai_2_ai_assistant_capabilities.md` (old) + `mai_2_ai_accelerator_not_decider.md` (new) both present, both order 2. This is why FR collided far worse than EN (FR mai was very stale). **Fix idea:** extractor should remove `core_content` files whose marker is no longer in methodology (the canonical marker→filename set).

## Process gaps

3. **Drift accumulates silently** because extraction isn't run after methodology edits. core_content was behind methodology in m0/m2/m4/m5/m6/m7/mai. **Fix:** git pre-commit hook / CI that runs `00_extract_slides.py` + `validate_content.py` and fails if core_content is stale.
4. **FR is much more drifted than EN** — FR extraction is rarely run. Always extract both langs.
5. **Never hand-edit `core_content`** — it's generated; edit `methodology/` then extract. (Done wrong once for the m4 completeness fix — consistent, but not the proper path.)
6. **m9 `_meta.yaml` must be protected** during extraction — m9 slides are manually managed, but the extractor regenerates their `_meta` and scrambles the ordering. Restore `m9*/_meta.yaml` after any extraction.
