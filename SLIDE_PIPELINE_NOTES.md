# Slide pipeline — issues to iron out / ways to work better

Working notes from the 2026-05-22 cleanup. Source of truth = `methodology/`; `core_content/` is generated by `tools/00_extract_slides.py` (which calls `migrate_to_meta.build_meta_yaml`).

## ⚠️ Biggest finding: methodology and core_content have STRUCTURALLY DIVERGED

methodology has **150 SLIDE markers** but core_content (extracted modules m0–m8 + mai) has **205 slide files**. A fresh extraction only produces ~134 files and would **prune ~92 real, in-use slides per language** (m4 DQA, most of m6/m7/m8, mai). So core_content holds substantial content methodology has **no marker for**, and some slides collide on one marker (two `m4_1b_*` files → one `m4_1b` marker).

**Implication:** the "methodology → extract → core_content" flow is **not safely runnable today** — a clean resync loses/renames content. The committed core_content is effectively a curated, diverged source. Reconciliation needed before any full resync. Strategic options:
- **(A) Reconcile methodology → core_content:** give every distinct slide a unique marker id, add the ~55 missing markers. Big content job; restores the pipeline.
- **(B) Treat core_content as source, decouple/retire the extractor;** methodology becomes docs-only.
- **(C) Leave decoupled, sync manually** when needed (status quo).

## Confirmed bugs

1. **`extract_order` duplicate `order` values — FIXED** (`tools/migrate_to_meta.py`). Order parsed from the `mX_N[letter]` prefix collided (two `m4_1b_*` → `1.02`) and multi-letter suffixes (`3ab`, `s3bb`) fell through to `0`. Fix: broadened suffix parsing (legacy values preserved) + a tiebreak in `build_meta_yaml` that nudges equal `(variant, order)` apart so every slide is unique. Verified: dup-order warnings gone.

2. **Extractor never deletes stale files — prune added but OPT-IN** (`tools/00_extract_slides.py --prune`). Renamed slides leave old files behind (FR `mai_2_ai_assistant_capabilities` old + `mai_2_ai_accelerator_not_decider` new, both order 2). A `--prune` flag now removes files not written this run (only in extracted folders; m9 never touched). **Left OFF by default** because of the divergence above — with methodology incomplete, pruning deletes real content (it removed 92 EN / 100 FR in testing). Only enable `--prune` after reconciliation (A).

## Process gaps

3. **Drift accumulates silently** because extraction isn't run after methodology edits. core_content was behind methodology in m0/m2/m4/m5/m6/m7/mai. **Fix:** git pre-commit hook / CI that runs `00_extract_slides.py` + `validate_content.py` and fails if core_content is stale.
4. **FR is much more drifted than EN** — FR extraction is rarely run. Always extract both langs.
5. **Never hand-edit `core_content`** — it's generated; edit `methodology/` then extract. (Done wrong once for the m4 completeness fix — consistent, but not the proper path.)
6. **m9 `_meta.yaml` must be protected** during extraction — m9 slides are manually managed, but the extractor regenerates their `_meta` and scrambles the ordering. Restore `m9*/_meta.yaml` after any extraction.
